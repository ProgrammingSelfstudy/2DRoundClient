# UI 验收（网页端，资源版本 dev15；英雄详情 dev26、布阵 dev27）

验收方法：用测试号在浏览器里逐页打开，对照恢复出来的原版布局数据（csb 树）和 Lua 代码看位置、文字、图片和行为。没有原版运行画面可对照，所以"位置对不对"以布局数据为准，"样子对不对"只能靠肉眼。

测试号 21，等级靠 `?lev=30` 看高等级图标。窗口 1541×692（竖屏列居中）。

## 通过

| 页面 | 通过的部分 |
|---|---|
| 主城 | 顶栏（头像、等级、名字、战力、金币、钻石、第三种货币）；夜景分层和左右拖动；七个建筑牌位置；等级图标的行和列；八天登陆图标由服务器 10922 推出；右下"+"折叠按钮的滑出和回来 |

| 闯关页 | 关卡名、默认描述、右上每分钟奖励、底部奖励条（可拖动）、挑战 BOSS 按钮三种状态（挑战、前往下一章、需要等级） |
| 战斗 | 开场站位（我方左、敌方右）、背景两层、站立动画、出手动作、受击、伤害数字、血条、死亡消失、结算文字、点屏幕返回、胜利后关卡和金币更新 |
| 英雄页 | 英雄卡（品质框、头像、阵营角标、等级、星数）、底部容量 1/300 和加号 |
| 背包页 | 5 列格子底、一键出售按钮（背包为空时只有空格） |

## 与原版对照（2026-11-06，Mac 模拟器里的原版 com.mengyu.shubanhanghai.expert20，adb 截图）

原版截图放在会话临时目录，没有进仓库。对照后换上原版素材的页面：

| 页面 | 换上的原版素材 | 对照结果 |
|---|---|---|
| 英雄页 | `bigbg/hero/hero_bag_bg.jpg`（背景）、`hero_bag_bg_1.png`（羊皮纸窗口框）；布局里本来就有的四个页签、七个阵营图标（按 `setCampBtnPos` 的 58 宽 20 间距排开）、选中圈、布阵按钮 | 与原版截图一致 |
| 背包页 | `bigbg/bigbg_2.jpg`（图书馆背景）、`pattern/pattern_3.png`（纸面花纹条）、特效 640（E24120，顶部人物动画）、五个分类页签（`backpack_2/3`）、底部花边 | 与原版截图一致 |

这两页的窗口背景和窗口框在布局里是占位图 `Default/ImageFile.png`，原版靠 Lua 在运行时换成真图，所以查素材要看 Lua 的 `loadTexture`，不能只看布局。

仍然不同的地方（原版有、我们没有）：

- 主城右侧图标列后面的棕色底板和折叠箭头（`mainui_1036`，九宫格）。
- 主城左下角的伙伴模型（原版是 Spine 角色站在码头）。
- 各页签和图标上的红点（要服务器的红点状态）。
- 闯关页：原版截图时正在自动战斗，没有拍到面板，面板的对照还没做。

## 差异和缺口（按影响排序）

1. ~~背包页没有分类页签~~、~~英雄页没有阵营筛选和页签~~：已用原版素材补上，背包页签和英雄页阵营筛选都能切换（见提交 32549ab、2344a6c）。英雄页上方的四个页签（图鉴、幽灵、信念）和"布阵"按钮还没接。
2. **英雄详情窗口**（`herodetail.ts`，原版 `hero/hero_main_info_window`，dev26）：点英雄格子打开（拖动滚动不算点击），用原版背景 `hero_info_bg_def`、名字、阵营图标、星级、等级、战力、有 Spine 的英雄显示模型（`stand2`），"返回"关闭，切底部页签也关闭；属性区先空着，同时发 11063，回包到了按两列显示 16 项。用真实英雄在浏览器里看过（修罗：模型出现，生命 411、攻击 49、物防 31、速度 73、命中 1000、暴伤 1500）。没做：属性/技能/装备/天赋四个页签只有"属性"有内容（页签名"属性、技能、装备、天赋"是猜的，原版布局里四个都写着"装备"）；左右切换英雄、锁定、分享、重置、皮肤、评论按钮；升级、升星；共鸣；阵营背景（现在固定用默认背景）；属性项的名字和顺序是照常识排的，没和原版对过；资源版本里只有部分英雄有 Spine，其余只显示信息。
   - 布阵窗口（`formpanel.ts`，原版 `hero/form_go_fight_panel` 的主线模式，dev27）：点"挑战 BOSS"先发 11211（类型 0）并打开，不再直接开打。六个阵位按阵法放在 3×3 格子里（格子坐标取自 `FormGoFightPanel.nine_position`，阵法表和服务端 `formation.go` 的 `formCells` 一致），下方是英雄列表（和英雄页同一种格子，抽成 `herocell.ts`；已上阵的变暗，可按阵营筛选）；点列表里的英雄上阵（放进第一个空位，满了提示"上阵英雄已满"），再点或点阵位里的英雄下阵；战力是阵位里英雄之和；"保存布阵"发 11212，"开战"先保存再发 13003。在浏览器里用新号走过一遍：下阵、上阵、保存、开战、打赢第 1 关回到闯关页（关卡变成第 2 关）。没做：阵法更换窗口（阵法固定用服务端给的）、神器/阵营光环、精灵、一键上阵、跳过战斗、拖动换位、阵位上的英雄模型（现在画卡片）、阵位前中后排文字、保存后改动提示；两个按钮的位置是我挪开的（原版布局里叠在一起，由 Lua 按模式显示其一）。窗口只有一名英雄时只能验证单英雄的情况，多英雄上阵的排布没肉眼看过。
3. **闯关页**
   - 右边"通缉令"里没有 Boss 头像：`headicon/b<编号>.jpg` 这批图已用哈希反查补上（`resmap.py` 里按 `"b"..编号` 拼路径，找回 106 张，进资源版本 dev20 的 `icons/head/b<编号>.webp`）；`dramapage.ts` 现在按 关卡的怪物组 → 首领 → `head_icon`（`tables/battle_models.json` 的 `b`）把头像放进 `image_boss`，已在浏览器里看过（新注册号第一关显示海盗1号，画在"WANTED"框里）。
   - 左边"快速作战"按钮：原来叠着两行字，查清是布局里的小图标和"快速作战"文字本来就设为不可见（节点的 visible 标志，`csb_tree.py` 之前没读），按钮图 `battledrama_2007` 自带"快速挂机"沙漏。现在读出 visible 并在 `ui.ts` 里照做（dev21，影响 5 个布局：闯关、英雄、背包、物品格、主城），按钮显示为带"快速挂机"字样的沙漏；英雄、背包、主城页对照没变化。"挑战 BOSS"和"详情"除了挑战外还没接。
   - 快速作战窗口（`quickwindow.ts`，原版 `battle_drama_quick_battle_windows`，dev22）：点按钮打开，列出最新通关关卡的掉落（`quick_show_items`），显示"本次免费"或"今日剩余 N 次"，按钮发 13004，关闭靠叉号和背景；新号发 13004 服务器回"通关指定关卡后开启快速作战"，往返已核对（控制台）。没做：特权次数和付费确认、说明提示、远航情报溢出提示、活动 UP 标；回复的提示文字在无头浏览器里没截到，没有肉眼确认。
   - 收益弹窗（`hookreward.ts`，原版 `battle_drama_hook_reward_windows`，dev23）：服务器推 13007（快速作战 type 2、领挂机收益 type 1）时打开，显示等级、经验条（从旧经验涨到新经验，升级就先涨满再从头走，每 10 毫秒涨 1%，经验上限取自新表 `tables/role_exp.json`）、"快速作战：/挂机收益："时长、物品格（4 列，超过一行可拖）和 vip 加成提示，点背景或底部提示条关闭（打开后 0.3 秒内不响应）；素材用 `levupgrade` 图集（新资源组）。用 `?rewarddemo=1` 的假数据在无头浏览器里看过，物品和文字都对。没做：头像（框里是空的）、标题的 Spine 特效（278）、物品品质框；没用真实 13007 推送走过一遍（新号没法快速作战）。布局里 `list_view` 的顶边（y 604）压在"获得物品"标题（y 532）上，原版运行时一定另有摆法，这里按标题下沿放，位置没和原版对过。没有暗底：布局的 `background` 没带图。
   - 描述一直是默认的"《ONE PIECE》"，原版表里没有描述字段，这点与原版一致，但没有核实过。
4. **战斗**
   - 没有技能特效、没有精灵（位置 41），布阵面板见闯关页一节。
   - 胜利窗口（`battlemvp.ts`，原版 `battle/battle_mvp_view` 的 `BattleMvpView`，dev24）：闯关打赢后服务器推 13016，这个窗口取代了原来的"战斗胜利"横幅；显示 MVP 标题、总伤害和占比、等级经验条、奖励物品（每行 4 个，超过一行可拖）、"确定"按钮（0.5 秒后出现）和 10 秒倒计时，到点或点确定回到闯关页。用 `?mvpdemo=1` 的假数据在无头浏览器里看过；没有用真实打赢一场走过。没做：MVP 英雄的半身像和名字、角色头像、特效（274、275、156）、"数据统计"窗口（按钮先藏起来）、"返回玩法"按钮、"当前战斗"一行。服务器原来把 13016 的 `lev`、`exp`、`new_lev`、`new_exp` 都发成 0，窗口遇到 0 就隐藏经验条；现在服务器填了角色的等级和领奖前后的经验（等级不变，角色在自己的窗口里升级），窗口遇到 0 仍隐藏。新网关起来后在浏览器里真打赢第 1 关看过：经验条 Lv.1 的 100/120，奖励四项（船长经验、英雄经验、贝里、远航情报），总伤害 812(100.00%)，倒计时和自动关闭都对。失败的战斗仍是横幅。
   - 战斗背景写死第一章的地图 10008；发布包（dev25）里有 `H30009`、`H30012` 和第 2 到 12 关的怪物模型（`H30022`、`H30018`、`H30088`、`H30030`、`H30066`、`H30055`、`H30007`、`H30014`，动作文件和 `H30012` 对过，多 3.5 MB）；用新号在浏览器里连打了第 1、2 关，都打赢、推进到第 3 关，控制台没有模型报错，战斗中截到的一张只有我方英雄，敌人已不在画面里（可能已被打倒，也可能没画出来，没有分清），怪物的样子还没有肉眼确认。第 12 关以后的怪物和别的英雄还缺模型，战斗背景也只有第一章。
   - 技能动作按技能编号猜（普攻 action1，技能 1、2、3 依次 action2、action3、action5），不是原版规则。
   - 战斗只有一回合就结束的关卡测过；多回合、多波怪、召唤、状态没测。
5. **主城**
   - "海楼石商城"等 5 个字的图标名超出图标宽度，贴到屏幕右缘；原版是否同样要对照。
   - 第 1 个页签"主城"没有选中态的凸起。
   - 左边缘的建筑牌（商城、召唤）被屏幕裁掉一半，这是场景可拖动所致，不是错误。
   - 服务器只报八日登录一个活动图标，其他活动图标没有。
6. **没有验收**：登录页（本轮没登出）、英雄详情、公会、历练、神技三个页签（还没有页面）。

## 风险

- 战斗的服务器流程会真实发放奖励并推进关卡，测试时每打一场测试号就前进一关。
- Spine 版本警告（3.4.02 对 3.8.99）一直在控制台，目前不影响显示。
- 3001 个原版 `.skel` 里有 3 个转不了（一个是 3.3.07 版本，两个读不出来）；遇到时才会发现。
