# 2DRound H5 外网试玩开发计划

开工日期为 2026-11-12，代码由 Codex 实现。首轮用手机移动数据登录自建测试服、进入主城、播放五星技能预览、打一场真实主线并看到结算。玩家遇到掉线、卡顿或操作问题时，可以在 H5 提交反馈，管理后台能查到工单。

当前基线为本机 Cocos `web-mobile` 和 dev54 资源。H5 页面、发布配置和清单均已返回 HTTP 200。五星技能预览已有本机验收，外网链路以手机蜂窝网络实测为准。 [技能预览验收](UI_ACCEPTANCE.md)

## 1. 明天先打通 HTTPS 登录和 WSS

- `mini/assets/scripts/boot.ts` 将写死的 `ws://当前主机:8802/ws` 改成可配置的入口。首轮使用测试站同源 `wss://<测试域名>/ws`，本机开发继续由配置选择可用地址。关闭发布版的 URL 密码和自动登录调试参数。
- `web/src/login.ts` 将 H5 登录和注册的密码移到 POST 请求体，保留 `client=h5` 账号分流，再运行 `python3 shared/sync_ts.py` 更新 Cocos 共享文件。服务端 `internal/login/http.go` 增加 H5 POST，保留原生客户端的兼容行为，应用与代理均按路径记录请求。鉴权响应设为不可缓存。本机 `mini/serve.py` 同步支持这两条 POST 路由。
- `boot.ts`、`cdn.ts` 和 `loginpage.ts` 将版本检查、资源加载、连接游戏和进入主城的失败显示在可操作的界面上。配置或清单不可用时显示不依赖素材的状态和重试入口，重试期间避免重复提交。
- 用新建 SQLite 测试库演练 Go 登录、网关和后台。Vercel Sandbox 只发布玩家 HTTPS 入口，代理提供 H5、dev54 资源、`/ws`、发布配置、区服列表、H5 登录和注册。网关控制、管理后台及旧兼容入口留在受保护的访问范围。先通过 WSS 升级和实际二进制登录，再跑手机游戏流程。 [Vercel Sandbox](https://vercel.com/docs/sandbox) · [Vercel WebSocket](https://vercel.com/docs/functions/websockets)

## 2. 加断线恢复和体验反馈

- 在主城接入已有 WebSocket 状态事件。前台使用现有 `1169` 心跳，切回前台时检查连接。断线显示“重新连接”，用有效 token 重新进入原角色并刷新服务器状态。明确的鉴权失败才清理 token，涉及消耗或领取的请求由玩家重新确认后提交。
- 在主城提供“反馈”，复用已有 `10810` 工单和管理后台工单列表。标题最多 50 字、正文最多 500 字。玩家可以描述卡顿、掉线、显示或操作问题。可复制 H5 版本、资源版本、页面和复现步骤。断网时留稿，收到服务器确认后显示成功。

2026-11-11 已接入反馈。提交时附最近 32 条游戏操作，提交前可展开查看。已用 Android Chrome 连接隔离测试服填写并提交，并从 Go 管理后台打开同一工单核对日志。本机 H5 和管理后台已更新。

## 3. 手机验收与分享条件

1. 关闭 Wi-Fi，用手机移动数据打开 HTTPS 链接，登录测试账号并进入主城。打开一个五星技能预览，完成一场主线战斗，刷新后核对角色和进度。
2. 切后台再回来，切换 Wi-Fi 与移动数据，再主动断开一次连接。核对提示、手动重连、同角色回城及服务器进度。模拟配置或清单失败，确认页面能显示状态并重试。
3. 从 H5 提交一条测试反馈，后台核对正文和角色归属。先记录首页可操作、登录到主城、首场战斗开始和重连耗时，再按实测决定优先优化项。

第 1 项跑通后可分享标明有效时段的外网试玩链接。第 2、3 项通过后验收断线恢复和游戏内反馈。Sandbox 到期会中断会话。首轮结束后，用跨实例状态与推送、持久库迁移和重启恢复评估 Vercel Functions 的长期方案。若 Sandbox 的 WSS 升级或游戏协议失败，保留可重跑的本机包和失败步骤，先验证独立的 WSS 链路。
